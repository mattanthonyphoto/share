How to fix the mobile speed

Ordered by what actually moves the number. Downloading is only 0.2s — so shrinking images is not the fix.

  1. Remove the duplicate Google Analytics GA4 is loading twice — once directly and again through Google Tag Manager. That is 280KB of tracking code, 133KB of it never used, all competing for the phone's processor while the page is trying to draw. Keep one, delete the other. Biggest controllable win
  2. Give the header its own styling, inline The navigation sits inside a custom code block, so it cannot appear until Squarespace's own 110KB stylesheet finishes — 3.2 seconds on its own. Putting the handful of styles the header needs directly in the block lets it draw immediately instead of waiting. Targets the 11.9s
  3. Preload the logo The logo is the element Google measures, and it is not discovered until late — that is the 2.6 second "finding the file" segment. One preload line in Squarespace's header code injection removes most of that wait. Targets the 2.6s
  4. Trim what else runs in code blocks Every custom script queues behind the platform's own. Defer anything that is not needed for the first screen, and drop anything unused. Targets the 11.9s
  5. Resize the hero images anyway 862KB heavier than they need to be. This will not move the speed score much, but it will help people on slower connections and is a two-minute change. Helps real visitors

The honest ceiling

Roughly 3.2 seconds of the delay is Squarespace's own stylesheet, which cannot be removed on this plan. Doing everything above should land mobile somewhere in the 65–75 range — a real improvement, and enough to stop it hurting. Reaching 90+ needs the custom-coded rebuild.
